# Player-local runtime host contract

This package defines storage-neutral DTOs, the asynchronous
`PlayerLocalAuditStorage` interface, pure validators, and the MoonBit checkpoint
policy wrapper shared by Node/mobile SQLite and browser IndexedDB. It contains
neither game rules nor a database-specific API.

`key-lifecycle.ts` provides storage-neutral key history with `key_id/version`,
purpose/scope, public key, validity windows, effective revocation, and
key-bound canonical signatures. Provisioning validates and indexes history
once; authority verification uses exact O(1) key lookup on the hot path. The
detailed semantics and custody limits are documented in the
[key lifecycle contract](../../docs/key-lifecycle-ja.md).

`crypto-backend.ts` defines asynchronous SHA-256/Ed25519 host I/O, a standard
WebCrypto adapter, and fail-closed experimental/production admission. The sync
MoonBit adapter and async host adapter share known-vector conformance tests and
the same pure key-lifecycle preflight. `digest-verification-plan.ts` executes
bounded canonical statements generated by MoonBit with the shared WebCrypto
backend; it never reimplements domain framing or game predicates.

Physical adapters never derive write sets from unauthenticated network data.
They apply DTOs returned by `MoonBitCheckpointPolicy.prepareWriteSet` in a CAS
transaction. `conformance.node.ts` runs the same restart, fault rollback, stale
revision, and ACK-capacity reuse suite against both implementations.

Current adapters:

- `examples/node-audit-runtime`: Node 24 `node:sqlite`
- `examples/cf-game-audit/web/src/audit/player-local-indexeddb.ts`: browser
  IndexedDB

Both adapters implement durable retention anchors for acknowledged contiguous
prefixes, appeal floors, protected epochs, equivocation pins, and four-point
fault rollback. Authenticated fork/challenge/appeal references are durable
evidence holds. Active holds protect their epoch independently of caller prune
requests; resolved holds are deleted only with the corresponding checkpoint
prefix. Placement and resolution advance the revision and invalidate stale
prune requests.

`evidence-hold-wire.ts` binds source ID, hold/message ID, boundary,
checkpoint/reference, decision, continuous per-source sequence, and previous
message digest into a domain-separated canonical statement behind a
crypto-independent authenticator interface. The verified mutation and next
hash-chain cursor commit in one revision-CAS transaction. Exact
sequence/digest retries are `no_change`; gaps, wrong previous digests, and
same-sequence conflicts fail closed. The configured genesis digest is checked
on the first message and the durable cursor becomes authoritative thereafter.

`evidence-inbox-polling.ts` defines cursor-bound POST/page DTOs and a bounded
decoder. The browser reference defaults to 128 messages and 1 MiB per page and
supports request timeouts and receive deadlines. HTTP, timeout, deadline, byte,
or page-limit failure leaves the database unchanged. If a later message in a
page is invalid, the already authenticated hash-chain prefix remains committed
message by message and polling resumes from its durable cursor.

Polling is a durable per-source job containing endpoint, genesis digest,
deadline, next-poll time, consecutive failures, a monotonic attempt token, and
`scheduled`/`in_flight`/`expired`/`escalated` state. Claim leases are capped by
the deadline. Completion CAS checks both token and lease expiry, so a stale
response cannot overwrite a restart-time reclaim. Success resets failures;
failure reschedules with MoonBit's deadline-capped exponential backoff. Expiry
or escalation stops only retrieval and never dismisses an active hold.

Mobile SQLite, encryption at rest, game-specific appeal/case adjudication, and
hierarchical Merkle-proof pruning remain pending.
